<product_requirements>
The goal is to build MesaERP, a production-ready, multi-tenant SaaS application for small to medium-sized restaurants and retail businesses. The platform aims to centralize finance, POS, inventory, procurement, and HR/KPI tracking.

**Core Features Implemented:**
- **Authentication & Multi-Tenancy:** Users can sign up, create an initial tenant (company), and log in.
- **Multi-Company Architecture:** The system supports a parent company with linked subsidiaries and business units. The workflow requires users to select a company immediately after login, with the ability to switch between companies.
- **POS Integration:** Integrated with the Parrot POS API to sync sales data. This includes handling authentication, correct endpoint routing, and rate-limiting.
- **Finance Module:** Users can view a chart of accounts and add manual journal entries. Financial data is filterable by business unit.
- **Settings & Customization:** A comprehensive settings page allows administrators to:
    - Manage companies (create subsidiaries) and business units.
    - Manage external API keys for the selected company.
    - Customize branding by changing dashboard colors and uploading a company logo.
    - Add and manage users with role-based permissions (view-only, edit access, etc.).

The primary focus has been on establishing the core multi-tenant structure, integrating a live POS system, and building out the administrative capabilities to manage the organizational hierarchy and user access.
</product_requirements>

<key_technical_concepts>
- **Tech Stack:** FastAPI (Python) backend, React frontend, and MongoDB database.
- **Multi-Tenancy:** Data is isolated at the application level, with  and  used in database models and API endpoints to ensure data separation.
- **API Integration:** Connection to the external Parrot POS API using a Bearer token, with implemented error handling for 404s and rate-limiting (429 errors) via exponential backoff.
- **Backend Architecture:** RESTful API with Pydantic models for data validation and serialization. Addressed recurring MongoDB  serialization issues by cleaning data before sending responses.
